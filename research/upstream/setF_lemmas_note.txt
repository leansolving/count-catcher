Two unproved lemmas in the LeanSAT pinned by the cpog VerifiedChecker: the details

1. What we found. The archived VerifiedChecker (cpog a97ed85, tag v1.2.0, the Zenodo record of the JAIR paper) pins LeanSAT to 1e13508, the head of LeanSAT pull request 8 (ppa-tauto, closed unmerged). That revision contains 17 sorries. Two of them are in the dependency closure of main and checkProof: Array.getElem?_setF and Array.getElem?_setF' in LeanSAT/Upstream/ToStd.lean, lines 401 to 407. They enter through PPA.varValue?_setVar and PPA.varValue?_setVar_of_ne, which ClauseDb.propagateUnitsHinted uses, so #print axioms lists sorryAx for main, checkProof, checkProofStep, addAt, delAt and addSum, and not for checkFinalState, initial, addProd, setRoot or the counting theorems. The checker's own sources have been sorry-free since c1b510a; the two remaining sorries sit in the dependency. axioms_report.lean and its output axioms_report.out show this; every Lean file here was run with the checker's own toolchain (Lean 4.4.0-rc1) and packages.

2. The second lemma is false as stated, because setF pads the array: for A = #[7], i = 3, j = 1, v = 5, default = 9 the left side is some 9 and the right side none. setf_false.lean derives False from it. The lemma holds when j < A.size or i < j and fails at the padding positions A.size <= j < i. The first lemma is true.

3. No consequence for the verdicts. The two PPA lemmas that use them are true: setVar pads with 0, and varValue? reads 0 as unassigned because the generation counter is positive, so a padded cell reads like an index outside the old array. ppa_patch.diff proves both directly (LeanSAT/Data/PPA.lean only; it adds a case analysis of setF reads and replaces the two proof bodies; no definition and no statement changed). With it, main and checkProof depend on propext, Quot.sound and Classical.choice only. The generated C files and the object files of the patched build are byte-identical to the archived build's, and linked on the same host the two executables are identical. In our runs (91 certificates from D4 outputs, the comparison of issue 3) the verified checker reported the correct count every time.

4. Suggestion. Pin a LeanSAT revision in which the two lemmas are proved, or apply the patch to the archived checker, and name the dependency in the README of the Zenodo record; the caveat on unverified array and hashmap operations in section 10 of the JAIR paper does not name it. On the current main of FormalSAT/trestle the same statement is still closed by sorry (Experiments/ProofChecking/Array.lean), while Experiments/SR/SetF.lean has a correct case analysis of setF reads.

Files: axioms_report.lean, axioms_report.out, setf_false.lean, ppa_patch.diff.
